# 교수자용 안내 — 과제 제출 운영 (학교 LMS · GitHub Classroom)

> 이 문서는 **교수자 전용**입니다. 수업 사이트(홈·주차 페이지)에는 노출되지 않습니다.
> 학생용 제출 방법은 사이트의 **`guide.html` (환경·제출 안내)** 3번을 보세요.

## 운영 방침

- **초기(이번 학기): 학교 LMS 로 제출** — 학생이 GitHub에 익숙하지 않으므로,
  익숙한 LMS로 답안 파일 + 결과 캡처를 제출받습니다. (사이트 안내도 LMS 기준으로 되어 있음)
- **향후(다른 수업 포함): GitHub Classroom 도입** — 아래 2~9절에 설정·채점 절차를 정리해 두었습니다.
  준비가 되면 그대로 따라 하면 됩니다.

---

## A. 초기 운영 — 학교 LMS 로 받기

1. LMS에 **주차별 과제 항목**을 만듭니다. (제목 예: `week03 데이터 필터링`, 마감일 지정)
2. 과제 설명에 **수업 사이트의 해당 주차 페이지 링크**와 "답안 파일 + 결과 캡처 제출"을 적습니다.
   - 사이트가 GitHub Pages로 공개돼 있으면 예: `https://dulis-1508.github.io/DB/week03/`
3. 학생 제출물: `week03_홍길동.sql`(또는 워드/한글) + 결과 캡처 이미지.
4. **채점**: 제출된 SQL을 우리 **웹 연습창(도서관 DB)** 또는 MySQL에 붙여 실행 → 결과를 확인하고,
   교수자용 **모범답안**(`solutions/weekNN_solution.sql`, zip으로 전달)과 대조합니다.
   - 채점 기준: 정확성 60 / 적절성 30 / 완성도 10. 같은 결과의 다른 풀이도 인정.
   - 점수·피드백은 LMS 성적/코멘트 기능으로 남깁니다.
5. 장점: 학생이 새 도구를 배울 필요가 없어 **초반 진입장벽이 없음**. 사이트의 문제·웹 연습창은 그대로 사용.

> 아래 B(그림 요약)부터는 **향후 GitHub Classroom 도입**을 위한 안내입니다. 지금 당장은 참고만 하세요.

---

## B. (향후) GitHub Classroom 도입 — 큰 그림 (5분 요약)

```
[1] GitHub 계정·조직(Organization) 준비   ─┐  (학기당 1회)
[2] GitHub Classroom에서 강의실 만들기      ├─ 학생 명단 없어도 지금 가능
[3] 과제(assignment) 만들기 — 템플릿 연결   ─┘
        │
        ▼
[4] 초대 링크 복사  →  (수강신청 확정 후) 학생에게 공지   ← 학생이 정해지면 이때!
        │
        ▼
[5] 학생이 링크 클릭 → 각자 과제 저장소 자동 생성 → 답 제출
        │
        ▼
[6] 교수자: 학생별 저장소에서 answer.sql 확인·실행·채점·피드백
```

**Q. 학생이 아직 미정인데 지금 준비해도 되나요?**
→ **네.** [1]~[3]은 학생 명단 없이 지금 다 만들 수 있습니다.
**초대 링크만 수강신청 확정 후 [4]에서 공지**하면 됩니다. 명단(roster)은 나중에 추가하거나,
학생이 링크로 들어올 때 스스로 이름을 고르게 할 수도 있습니다.

---

## 1. 준비 (학기당 한 번)

1. **GitHub 계정**: [github.com](https://github.com) 가입 (이미 있으면 그대로 사용).
2. **조직(Organization) 만들기** — 무료.
   - 우측 상단 `+` → **New organization** → **Free** 플랜 선택.
   - 조직 이름 예: `dulis-2026-db` (수업/학교 알아보기 쉽게).
   - *조직을 쓰는 이유*: 학생 과제 저장소를 한곳에 모아 관리·채점하기 위함.
3. **GitHub Classroom 활성화**:
   - [classroom.github.com](https://classroom.github.com) 접속 → GitHub 계정으로 로그인.
   - **New classroom** → 위에서 만든 조직 선택 → 연결 허용(Authorize).

---

## 2. 강의실(Classroom)과 명단(Roster)

1. Classroom 이름 지정 예: `2026-2 데이터베이스`.
2. **Roster(명단)**:
   - 지금은 **비워 두어도 됩니다.** (Skip / 나중에)
   - 수강신청 확정 후 학생 이름 목록(엑셀 붙여넣기)으로 추가하면,
     학생이 링크로 들어올 때 "본인 이름 선택" 화면이 떠서 누가 누군지 매칭됩니다.
   - 명단을 안 써도 됩니다. 그 경우 학생의 GitHub 아이디로 구분합니다(이름 매칭은 수동).

---

## 3. 과제(Assignment) 만들기 — 주차별

> 매주 하나씩 만드는 것을 권장합니다(주차별 마감일 관리가 쉬움). 처음엔 1개만 만들어 흐름을 익히세요.

1. Classroom → **Assignments** → **New assignment**.
2. **기본 설정**
   - **Assignment title**: 예 `week03-데이터필터링`.
   - **Deadline**: 주차 마감일(선택).
   - **Individual**(개인 과제) 선택. *(팀 과제 아님)*
   - Visibility: **Private** 권장(학생끼리 답을 못 보게).
3. **Starter code(템플릿) 연결** — 학생에게 나눠줄 시작 파일:
   - **Add a template repository** 에서 이 수업 저장소(`DULIS-1508/DB`)를 선택하거나,
     과제용으로 **해당 주차 폴더만 담은 가벼운 템플릿 저장소**를 지정합니다.
   - *권장*: 학생 저장소가 가벼우려면 `weekNN/README.md` + `weekNN/answer.sql`만 담은
     **전용 템플릿 저장소**가 깔끔합니다. (원하시면 만들어 드립니다 — 아래 8번 참고.)
   - ⚠️ **정답지(`solutions/`)가 템플릿에 포함되지 않게 하세요.** 본 저장소는 `solutions/`를
     `.gitignore`로 제외해 두었으니 안전합니다.
4. (선택) **Autograding**: 자동 채점은 SQL 특성상 설정이 번거로우니 **처음엔 생략**을 권장합니다.
   본 수업은 교수자가 직접 실행·확인하는 방식으로 충분합니다.
5. **Create assignment** → 완료되면 **초대 링크(invite link)** 가 나옵니다. 복사해 둡니다.

---

## 4. 초대 링크 공지 (학생이 정해진 뒤)

- 수강신청 확정 후, **각 주차 과제의 초대 링크**를 학교 LMS 공지/이메일/카톡 등으로 학생에게 전달합니다.
- 학생 행동: 링크 클릭 → **Accept this assignment** → 본인 과제 저장소 자동 생성 → 브라우저에서
  `answer.sql` 편집(연필✏️) → **Commit changes** 로 제출. (사이트 `guide.html` 3번에 그림 없이도
  따라 하도록 상세히 적어 두었습니다.)

---

## 5. 제출 확인과 수집

- Classroom → 해당 Assignment 를 열면 **학생별 저장소 목록과 제출 여부**가 표로 보입니다.
- 개별 저장소를 클릭하면 학생이 올린 `answer.sql`·`result.png`를 브라우저에서 바로 볼 수 있습니다.
- 전체를 한 번에 받고 싶으면 각 저장소에서 **Code → Download ZIP**, 또는
  Classroom의 다운로드 기능/`GitHub Classroom Assistant` 앱을 사용합니다.

---

## 6. 채점하기

1. 학생의 `answer.sql`을 엽니다.
2. **정답 실행·대조**: 답 SQL을 우리 **웹 연습창(도서관 DB)** 또는 MySQL에 붙여 실행해 결과를 봅니다.
   - 교수자용 **모범답안·채점 포인트**는 zip으로 전달드린 `solutions/weekNN_solution.sql`에 있습니다.
   - 같은 결과를 내는 다른 풀이도 정답으로 인정하세요(예: `IN` 대신 `OR`).
3. **채점 기준(사이트 4번과 동일)**: 정확성 60 / 적절성 30 / 완성도 10.
4. **피드백 남기기**: 학생 저장소에서
   - 파일의 특정 줄 옆 `+` → 코멘트, 또는
   - 커밋 화면에서 코멘트, 또는
   - 저장소 **Issues** 에 총평 한 줄.
   - 점수는 별도 성적표(엑셀)로 관리하는 것이 편합니다.

---

## 7. 자주 겪는 상황

| 상황 | 해결 |
|------|------|
| 학생이 "Accept"를 안 눌러 저장소가 없음 | 목록에 안 뜹니다. 링크 재공지, 마감 연장 안내 |
| 학생이 Commit을 안 눌러 빈 파일 | 제출 전이므로 0점 처리 전 재안내 권장 |
| 학생이 결과 캡처를 안 올림 | 완성도(10%)에서 감점, 재제출 안내 |
| GitHub 계정 오류 | 이메일 인증 미완료가 대부분. 인증 메일 확인 안내 |

---

## 8. GitHub이 부담되면 — 더 쉬운 대안

학생 대다수가 GitHub에 어려움을 겪으면, **초반 몇 주는 아래로 대체**하고 익숙해지면 GitHub으로 옮겨도 됩니다.

- **학교 LMS 과제 업로드**: 학생이 `answer.sql`(텍스트)과 결과 캡처를 LMS에 업로드 → 교수자가 내려받아 채점.
- **Google Classroom / Google Forms**: 폼에 SQL 붙여넣기 + 캡처 업로드 → 스프레드시트로 수집.
- 이 경우에도 **웹 연습창·주차별 과제 페이지는 그대로** 사용하면 됩니다. 바뀌는 건 "제출 창구"뿐입니다.

> 원하시면 (1) 주차별 `answer.sql`만 담은 **가벼운 Classroom 템플릿 저장소**,
> (2) LMS/구글폼용 **제출 양식**을 만들어 드리겠습니다. 말씀만 주세요.

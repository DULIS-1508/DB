# 도서관 데이터베이스로 배우는 데이터베이스 개론 — 집필 마스터 플랜

> **한 줄 콘셉트**: 국내 데이터베이스 입문 개론서의 **개념·목차 뼈대는 유지**하되,
> 모든 사례·예제·실습 데이터를 **실제 도서관 데이터베이스**(국립중앙도서관·국회도서관·
> 공공도서관·대학도서관)로 채운 **문헌정보학 특화 데이터베이스 입문서**.

- **버전**: v0.5 (초안)
- **성격**: 기존 강의(수업계획)와 **무관한 독립 집필 프로젝트**
- **분량**: 총 **13장**, 이미지·사례 예시 포함 **약 300~400페이지**
- **주 독자**: 문헌정보학과 데이터베이스 개론 수강생, 도서관 실무 입문자
- **골격 기준**: 국내 표준 개론서의 **13장 체계**를 계승
- **사례 기반**: 실제 도서관 기관이 **개방(Open API·LOD·공공데이터)** 한 데이터를 사례로 활용
- **선수 지식**: 없음(프로그래밍 무경험 가능), MySQL/MariaDB 실습 병행

---

## 1. 기획 의도와 차별점

### 1.1 문제의식
시중의 데이터베이스 개론서는 대부분 MySQL 기반이지만 예제가 `사원-부서`, `쇼핑몰-주문`
같은 **일반 사례 중심**이다. 그래서:
- **문헌정보학과 학생**에게는 도메인이 낯설어 개념 학습에 어려움이 있고,
- **실제 도서관 현장의 데이터베이스**를 접근·활용하는 경험과는 상당한 거리가 있다.

### 1.2 이 책의 해법
- 개론서의 검증된 **개념 구조·목차는 계승**하되, 사례·데이터를 **실제 도서관 DB로 전면 교체**한다.
- 국립중앙도서관·국회도서관·공공도서관·대학도서관이 **실제로 개방한 데이터**(서지·소장·
  대출·통계)를 가져와, 학생이 **현장 데이터를 직접 만지며** 개념을 익히도록 한다.
- 도서관 표준(KORMARC, KDC/DDC, ISBN, 전거(authority), LOD/RDF)과 자연스럽게 연결해
  **전공 지식과 데이터베이스 기술을 동시에** 쌓게 한다.

### 1.3 두 축의 학습 구조(중요)
현장 데이터는 그대로는 실습이 어렵고 개방 정책도 바뀔 수 있으므로, 책은 **두 축**으로 구성한다.

1. **실습용 교육 스키마(Teaching DB)** — 실제 도서관 시스템을 본떠 저자가 설계한, 누구나
   MySQL에서 재현 가능한 도서관 데이터베이스. 모든 SQL 실습의 토대.
2. **실제 도서관 사례(Real Cases)** — 각 장마다 실제 기관의 데이터 구조·API·개방 데이터를
   사례로 제시하고, 일부 장에서는 실데이터를 내려받아 교육 스키마에 적재해 분석한다.

> **재현성 원칙**: 실제 API/LOD는 변경·중단될 수 있으므로, 사용한 실데이터는 **스냅샷 파일**
> (CSV/JSON/SQL)로 부록에 동봉해 API가 막혀도 책의 실습이 항상 재현되게 한다.

### 1.4 입문서 원칙 — 기본 개념 우선(중요)
이 책은 **입문 개론서**다. 따라서 데이터베이스의 **기본 개념을 책의 뼈대로 완결적으로**
다루는 것이 최우선이며, 도서관 사례는 그 개념을 **이해시키는 수단**이지 개념을 대체하지 않는다.

1. **개념 완결성**: 표준 개론서가 다루는 핵심 개념·용어를 하나도 빠뜨리지 않고, 도서관을
   전혀 몰라도 개념만으로 이해되도록 **자기완결적으로** 서술한다.
2. **개념 우선 서술**: 모든 장은 **개념 설명을 먼저·충분히** 한 뒤에 도서관 사례로 예시한다.
   (개념 → 사례 → 실습 순서를 절대 뒤집지 않는다)
3. **일반화 가능성**: 도서관 사례로 익힌 개념이 다른 도메인에도 그대로 적용됨을 짚어,
   특정 도메인에 갇히지 않게 한다.
4. **점진적 난이도**: 선수 지식 없이 시작해, 각 장은 앞 장 개념만으로 이해되도록 누적한다.
5. **개념 장치**: 각 장에 **핵심 용어 정리·개념 요약·확인문제**를 넣어 기본기를 고정한다.

## 2. 실제 도서관 데이터 소스 카탈로그

각 기관이 실제로 개방한 데이터·서비스. (URL·개방 상태는 집필 시점 재확인 필요)

| 관종 | 대표 시스템/서비스 | 개방 형태 | 대표 데이터 |
|---|---|---|---|
| **국립중앙도서관** | 국가서지 **LOD**(lod.nl.go.kr), 서지정보 개방 **Open API**, 국가자료종합목록 | LOD(RDF), Open API, KORMARC | 국가서지·전거·ISBN·소장정보 |
| **국회도서관** | 자료검색 Open API, **국가학술정보 OpenAPI**(losi-open.nanet.go.kr), 열린국회정보 | Open API | 학위논문·학술기사·단행본 서지 |
| **공공도서관** | **도서관 정보나루**(data4library.kr, 국중 운영, 전국 1,000+관) | Open API, 파일 | 대출·장서·인기/급상승 도서·지역 독서통계 |
| **대학도서관** | **RISS**(riss.kr, KERIS) API센터, 대학도서관 통계 | Open API, 통계 | 학술논문·학위논문·단행본, 대학도서관 통계 |

- **국립중앙도서관**은 KORMARC/DBMS 데이터를 RDF로 변환해 **Dublin Core·BIBO** 온톨로지 기반
  LOD로 발행 — 서지 표준·연계데이터 사례의 핵심.
- **정보나루**는 실제 **대출 데이터**를 개방하는 국내 유일급 소스 — SQL·통계·빅데이터 사례의 보고.
  (※ 일부 서비스·Open API가 중단된 시기가 있어, 집필 시 개방 상태를 반드시 확인하고
  스냅샷 데이터로 대비한다.)

> **권장 운영**: **공공도서관(정보나루)** 를 실습의 "주(主) 데이터셋"으로,
> **국립중앙도서관(서지·LOD)** 을 서지 표준·연계의 "기준(backbone)" 으로 삼고,
> 국회도서관·대학도서관은 학술서지·통계 확장 사례로 배치.

## 3. 관통 교육 스키마 — 실제 도서관 시스템을 본뜬 실습 DB

실습용으로 저자가 설계하는 핵심 엔터티(초안). 실제 KORMARC 필드·정보나루 항목에서 도출.

| 엔터티 | 의미 | 실제 대응(예) |
|---|---|---|
| **book(자료/서지)** | 서지 단위 | KORMARC 245/260, ISBN, KDC, 제어번호 |
| **author(저자)** | 저자/역자 | KORMARC 100/700, 전거(authority) |
| **book_author** | 자료:저자 N:M | 공저·역자 역할 |
| **publisher(출판사)** | 발행처 | KORMARC 260$b |
| **copy(소장본)** | 물리 개별본 | 등록번호·청구기호·소장분관 |
| **member(회원)** | 이용자 | 회원 유형(학생/교직원/일반) |
| **loan(대출)** | 대출/반납 | 정보나루 대출 이벤트 |
| **reservation(예약)** | 예약 | 대출중 자료 예약 |
| **fine(연체료)** | 연체·분실 부과 | 연체료 규칙 |
| **branch(분관)** | 도서관/분관 | 정보나루 도서관 코드 |
| **kdc_class(분류)** | KDC 참조 | 한국십진분류 |

자료(book) : 소장본(copy) = 1:N · 소장본 : 대출(loan) = 1:N · 회원 : 대출 = 1:N · 자료 : 저자 = N:M

## 4. 전체 목차 — 표준 개론서 13장 + 실제 도서관 사례

> **장 구성(고정) — 개념부 + 도서관 응용·사례부의 2블록 구조**
>
> - **A. 개념 학습부**(도메인 중립) — 데이터베이스 기본 개념·용어·원리를 도서관을 몰라도
>   이해되도록 **자기완결적으로** 설명. 이 책의 **중심**.
> - **B. 도서관 응용·사례부** — A에서 배운 개념이 실제 **도서관 DB·DBMS·관계형/ER 모델**에서
>   어떻게 구현·활용되는지 **구체적이고 상세하게** 보여줌. 개념의 **적용 확인**.
> - **C. 실습부** — 교육 스키마로 직접 SQL 실습.
> - **D. 마무리** — 개념 요약·핵심 용어·확인문제.
>
> **학습 흐름**: *개념 이해(A) → 도서관 현장 적용 확인(B) → 직접 해보기(C) → 개념 고정(D)*.
> 아래 각 장의 "개념/사례/실습"은 각각 A/B/C 블록의 핵심 소재를 요약한 것이다.
> (한 장이 실제로 펼쳐지는 상세 예시는 **§9 장 구성 표본** 참조)

### 1부. 데이터베이스 기초 개념

**1장 — 데이터베이스 기본 개념**
- 개념: 데이터·정보, 데이터베이스의 필요성·정의·특징, 데이터 과학 시대의 데이터
- 사례: 네 관종이 다루는 데이터 스펙트럼(서지·소장·대출·통계), 정보나루 규모(전국 1,000+관)
- 실습: 도서관 데이터 항목 도출 워크시트

**2장 — 데이터베이스 관리 시스템(DBMS)**
- 개념: 파일시스템 문제점, DBMS 정의·기능·장단점, 데이터 독립성, 발전 과정
- 사례: KORMARC 텍스트 레코드 vs 관계형 저장 — 도서관이 DBMS를 쓰는 이유
- 실습: MySQL/MariaDB 설치·접속

**3장 — 데이터베이스 시스템**
- 개념: 3단계 스키마(외부/개념/내부), 사용자, 데이터 언어(DDL/DML/DCL), DBMS 구성
- 사례: OPAC(이용자 검색) = 외부 스키마, 국가자료종합목록 = 통합 개념 스키마, 사서 = DBA
- 실습: 사용자·스키마 계층 관찰

### 2부. 데이터 모델과 이론

**4장 — 데이터 모델링과 E-R 모델**
- 개념: 데이터 모델링, 개체-관계 모델, 카디널리티, 논리적 모델 변환
- 사례: 실제 KORMARC 필드(245·100·260·소장)에서 서지·소장·이용 개체 도출
- 실습: 도서관 ERD 작도 → 관계 스키마 초안

**5장 — 관계 데이터 모델**
- 개념: 릴레이션·튜플·도메인, 키(기본/후보/외래), 무결성 제약(개체·참조·도메인)
- 사례: ISBN·제어번호·청구기호를 키로, **전거(authority)** = 참조 무결성의 실제 사례
- 실습: 키 식별 워크시트, 제약 위반 관찰

**6장 — 관계 데이터 연산**
- 개념: 관계 대수(선택·투영·조인·집합), 관계 해석 개요
- 사례: 정보나루 대출 데이터에 "특정 분류·연령대 선택", "서명·저자 투영"을 관계 대수로
- 실습: 관계 대수식 ↔ 자연어 질의 상호 변환

### 3부. SQL 실습

**7장 — 데이터베이스 언어 SQL: 정의와 조작**
- 개념: SQL 소개, 데이터 정의(CREATE/ALTER/DROP·제약), 데이터 조작(INSERT/UPDATE/DELETE, SELECT·조인·집계·서브쿼리)
- 사례: 교육 스키마 구축 + 정보나루/국중 **실데이터 스냅샷** 적재
- 실습: 종합실습 — 인기 대출 도서 통계, 분류별 장서 분석

**8장 — 데이터베이스 응용 SQL**
- 개념: 뷰, 저장 프로그램(프로시저·트리거) 개요, 삽입 SQL, 파이썬+MySQL 프로그래밍
- 사례: 파이썬으로 **정보나루/국립중앙도서관 Open API** 호출 → MySQL 적재 → 분석·뷰 구성
- 실습: 종합실습 — API 데이터 파이프라인 만들기

### 4부. 설계와 정규화

**9장 — 데이터베이스 설계**
- 개념: 설계 단계, 요구사항 분석, 개념·논리·물리 설계와 구현
- 사례: 실제 공공/대학도서관 업무 요구를 요구분석 → 개념(ERD) → 논리 → 물리(MySQL)
- 실습: 종합실습 — 도서관 시스템 설계하기

**10장 — 정규화**
- 개념: 이상 현상, 함수 종속, 1~3정규형·BCNF(·4정규형 개요)
- 사례: **KORMARC의 반복 필드**(다중 저자·주제어)를 담은 평면표를 단계적으로 정규화
- 실습: 평면 대출대장 → 3NF 분해

### 5부. 운영과 확장

**11장 — 회복과 병행 제어**
- 개념: 트랜잭션·ACID, 장애와 회복, 병행 제어(락·직렬 가능성)
- 사례: 대출/반납을 트랜잭션으로, 다관(멀티 분관) 동시 대출·예약 충돌
- 실습: COMMIT/ROLLBACK, 격리수준·락 관찰

**12장 — 보안과 권한 관리**
- 개념: 데이터베이스 보안, 접근 통제, 권한 관리(GRANT/REVOKE), SQL 인젝션 개요
- 사례: 회원 개인정보·대출기록 보호(도서관법·프라이버시), 사서/이용자/관리자 권한 분리
- 실습: 계정·권한 부여, mysqldump 백업

**13장 — 데이터베이스의 확장과 최신 데이터 기술**
- 개념: 관계 DB의 한계·확장, 분산/병렬, 빅데이터·NoSQL, 클라우드·AI, 데이터 마이닝·시각화
- 사례: **국가서지 LOD/RDF·링크드데이터**, 정보나루 대출 빅데이터 분석·도서 추천·이용 시각화
- 실습: 종합 프로젝트 — 도서관 데이터 분석·시각화 또는 LOD/NoSQL 확장 설계

## 9. 장 구성 표본 — 4장 「데이터 모델링과 E-R 모델」

> 2블록 구조(개념부 A + 도서관 응용·사례부 B)가 실제 절(節) 수준에서 어떻게 펼쳐지는지
> 보여주는 표본. 다른 장도 이 뼈대를 그대로 따른다.

**4.0 이 장에서 배우는 것 / 핵심 용어 미리보기**

### A. 개념 학습부 — 데이터 모델링의 원리 *(도메인 중립, 이 절이 중심)*
- **4.1 데이터 모델링이란** — 현실 세계 → 데이터 모델로 추상화하는 3단계(개념·논리·물리)
- **4.2 개체(Entity)와 속성(Attribute)** — 개체 유형/개체 인스턴스, 속성의 종류(단순·복합·다중값·유도)
- **4.3 관계(Relationship)와 카디널리티** — 1:1, 1:N, N:M, 참여 제약(전체/부분)
- **4.4 개체-관계 다이어그램(ERD) 표기법** — 피터 첸 표기·까마귀발(Crow's Foot) 표기 비교
- **4.5 약한 개체와 식별 관계** — 식별자가 없는 개체를 어떻게 표현하나
- **4.6 ERD를 논리적 데이터 모델(관계 스키마)로 변환하는 규칙** — 개체·관계·N:M·다중값 속성 변환
- *(그림: 일반적인 ERD 예시 도식 — 도서관과 무관한 중립 예시 1개로 개념부터 이해)*

### B. 도서관 응용·사례부 — 개념이 도서관에서 이렇게 쓰인다 *(구체·상세)*
- **4.7 도서관의 개체 찾기** — 서지(자료)·저자·출판사·소장본·회원·대출을 실제 **KORMARC 필드**
  (245 서명, 100/700 저자, 260 발행)에서 개체·속성으로 도출
- **4.8 도서관의 관계 모델링** — 자료:소장본(1:N), 자료:저자(N:M), 회원:대출(1:N)을 왜 그렇게 보는가
- **4.9 헷갈리기 쉬운 지점** — "자료(서지)"와 "소장본(물리적 책)"을 **왜 다른 개체로** 나누는가
  (같은 책을 3권 소장 → 개체·인스턴스 개념의 실제 사례)
- **4.10 도서관 개념 ERD 완성** — 4.7~4.9를 종합한 전체 ERD 그림(이 책의 관통 스키마 원형)
- **4.11 실제 사례 엿보기** — 국립중앙도서관 국가자료종합목록/LOD가 서지·전거·소장을
  어떻게 개체·관계로 구조화했는지 캡처와 함께 비교
- *(그림: 도서관 ERD 완성본, KORMARC 레코드 → 개체 매핑 도식, LOD 그래프 캡처)*

### C. 실습부

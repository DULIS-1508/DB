# 도서관 데이터로 배우는 데이터베이스 개론 — 집필 마스터 플랜

> **한 줄 콘셉트**: 국내 MySQL 기반 데이터베이스 개론서의 **개념·목차 뼈대는 그대로**,
> 모든 예제·실습 데이터를 **하나의 도서관 데이터베이스**로 통일한 데이터베이스 교재.

- **버전**: v0.2 (초안)
- **성격**: 기존 강의(수업계획)와 **무관한 독립 집필 프로젝트** — 특정 학기·주차에 얽매이지 않음
- **관통 도메인**: 추상형(유형 혼합) 도서관 모델 — 특정 관종에 종속되지 않는 일반 도서관 DB
- **주 독자·수준**: 문헌정보학/데이터 관련 **학부 전공생** 및 도서관 실무자 입문
- **골격 기준**: 국내 표준 개론서(예: 『데이터베이스 개론』류)의 **13장 체계**를 따름
- **선수 지식**: 없음(프로그래밍 무경험 가능), MySQL/MariaDB 실습 병행

---

## 1. 기획 의도와 차별점

### 1.1 문제의식
국내 데이터베이스 개론서 대부분은 `사원-부서`, `학생-수강`, `쇼핑몰-주문` 같은
예제로 개념을 설명한다. 개념 전달에는 문제가 없지만, 문헌정보학 전공생이나 도서관
실무자에게는 **도메인이 낯설어 개념과 현장의 연결이 끊긴다.**

### 1.2 이 책의 해법
- **개론서의 검증된 목차·개념 구조는 그대로 계승**하되, 책 전체를 관통하는
  **단 하나의 도서관 데이터베이스**를 설계해 1장부터 마지막 장까지 **같은 스키마·
  같은 데이터**를 점진적으로 확장하며 모든 개념을 설명한다.
- 학생은 "회원이 책을 빌리고 반납하고 연체료를 내는" 익숙한 흐름 위에서
  키·정규화·트랜잭션·회복·보안을 **자연스럽게** 익힌다.
- 표준(ISBN, KDC/DDC 분류, 청구기호, MARC 개념)과 연결해 **전공 심화로 확장**한다.

### 1.3 설계 원칙
1. **표준 목차 계승**: 개론서 독자·강의자가 익숙한 장 구성·개념 순서를 유지한다.
2. **누적성**: 각 장의 스키마·데이터는 앞 장을 이어받아 확장한다(버리고 새로 만들지 않음).
3. **개념 → 도서관 매핑 → 실습(SQL) → 확인문제**의 4단 구성을 모든 장에서 반복한다.
4. **추상형 유지**: 실제 특정 도서관을 모사하지 않되, 현실 규칙(대출기간·연체·예약)은 반영한다.
5. **재현 가능성**: 모든 예제는 제공 SQL 스크립트로 누구나 동일하게 재현할 수 있다.

## 2. 관통 도메인 — 추상형 도서관 데이터 모델

교재 전체가 사용하는 핵심 엔터티(초안). 초반 장에서는 일부만 등장하고,
설계·정규화 장을 거치며 완성형으로 확장된다.

| 엔터티 | 의미 | 핵심 속성(예) |
|---|---|---|
| **자료(book)** | 서지 단위(제목 레벨) | ISBN, 서명, 출판사, 출판년도, KDC분류 |
| **저자(author)** | 저자/역자 | 이름, 국적 |
| **자료저자(book_author)** | 자료:저자 N:M 연결 | book_id, author_id, 역할(저자/역자/편저) |
| **출판사(publisher)** | 발행처 | 이름, 소재지 |
| **소장본(copy)** | 물리적 개별 자료(등록번호 단위) | 청구기호, 등록번호, 상태, 소장분관 |
| **회원(member)** | 이용자 | 이름, 유형(학생/교직원/일반), 가입일, 상태 |
| **대출(loan)** | 대출 트랜잭션 | copy_id, member_id, 대출일, 반납예정일, 반납일 |
| **예약(reservation)** | 대출중 자료 예약 | book_id, member_id, 예약일, 상태 |
| **연체료(fine)** | 연체·분실 부과금 | loan_id, 금액, 부과일, 납부일 |
| **분관(branch)** | 도서관/분관 | 이름, 위치 |
| **분류(kdc_class)** | 한국십진분류(참조) | 분류코드, 분류명 |

### 개념 ERD (텍스트 스케치)
```
publisher 1───N book N───M author        (book_author)
                 │
                 │ 1
                 ▼ N
                copy ───────N loan N─────── member
                 │                            │
                 │ N                          │ 1
                 ▼                            ▼ N
               branch                     reservation
                                             fine (loan 1───N)
```
- 자료(book) : 소장본(copy) = **1:N** (같은 책을 여러 권 소장)
- 소장본(copy) : 대출(loan) = **1:N** (한 권이 시간에 따라 여러 번 대출)
- 회원(member) : 대출(loan) = **1:N**
- 자료(book) : 저자(author) = **N:M** (공저·역자)

## 3. 전체 목차 — 표준 개론서 13장 체계

> 표준 개론서의 장 구성·개념 순서를 그대로 계승. 각 장은
> **[개론서 개념] → [도서관 데이터 매핑] → [MySQL 실습] → [확인문제]** 순서로 서술.
> (주차·학기와 무관한 "책"의 장 단위 구성)

### 1부. 데이터베이스 기초 개념

**1장 — 데이터베이스 기본 개념**
- 개념: 데이터베이스의 필요성, 정의와 특징(실시간 접근·계속 변화·동시 공유·내용 참조), 데이터 과학 시대의 데이터
- 매핑: 수기 대출대장의 한계 → 통합도서관시스템(ILS), 도서관이 다루는 데이터(서지·이용·통계)
- 실습: 도서관에서 관리할 데이터 항목 도출(개념 워크시트)

**2장 — 데이터베이스 관리 시스템(DBMS)**
- 개념: 파일시스템의 문제점(중복·종속성), DBMS의 정의·기능, 장단점, 데이터 독립성, 발전 과정
- 매핑: 부서별 엑셀로 흩어진 도서관 데이터를 DBMS로 통합하는 이유
- 실습: MySQL/MariaDB 설치·접속, `SHOW DATABASES`

**3장 — 데이터베이스 시스템**
- 개념: 3단계 스키마(외부/개념/내부), 데이터 독립성, 데이터베이스 사용자, 데이터 언어(DDL/DML/DCL), DBMS 구성
- 매핑: 사서(DBA)·이용자(최종사용자)·개발자 역할, 이용자 검색화면 = 외부 스키마
- 실습: 사용자·스키마 계층 관찰

### 2부. 데이터 모델과 이론

**4장 — 데이터 모델링과 E-R 모델**
- 개념: 데이터 모델링의 개념, 개체-관계 모델(개체·속성·관계, 카디널리티), 논리적 데이터 모델로의 변환
- 매핑: 도서관 개념 ERD 설계(자료·소장본·회원·대출·저자·출판사), N:M(자료-저자) 해소
- 실습: 도서관 ERD 작도 → 관계 스키마 초안

**5장 — 관계 데이터 모델**
- 개념: 릴레이션·속성·튜플·도메인, 릴레이션의 특성, 키(기본/후보/외래/대체), 무결성 제약(개체·참조·도메인)
- 매핑: 도서관 엔터티를 릴레이션으로, 대출의 외래키·참조 무결성
- 실습: 키 식별 워크시트, 제약 위반 사례 관찰

**6장 — 관계 데이터 연산**
- 개념: 관계 대수(선택·투영·조인·집합연산), 관계 해석(투플/도메인) 개요
- 매핑: "연체 회원 선택", "서명·저자만 투영", "대출 ⋈ 회원" 등 도서관 질의를 관계 대수로 표현
- 실습: 관계 대수식 ↔ 자연어 질의 상호 변환
- *(고전 개론서 수준으로 관계 해석·QBE를 더 깊게 다루는 확장 옵션 있음)*

### 3부. SQL 실습

**7장 — 데이터베이스 언어 SQL: 정의와 조작**
- 개념: SQL 소개, 데이터 정의(CREATE/ALTER/DROP, 제약조건), 데이터 조작(INSERT/UPDATE/DELETE, SELECT·조인·집계·서브쿼리)
- 매핑: 도서관 스키마 생성(`schema.sql`)·데이터 적재(`seed.sql`), 도서 검색·대출 통계 쿼리
- 실습: 종합실습 — 도서 검색기 / 대출 통계 리포트

**8장 — 데이터베이스 응용 SQL**
- 개념: 뷰, 저장 프로그램(프로시저·트리거) 개요, 삽입 SQL, 파이썬+MySQL 프로그래밍
- 매핑: `v_대출가능도서` 뷰, 반납 시 연체료 자동계산 트리거, 파이썬 도서관 조회 스크립트
- 실습: 종합실습 — 파이썬으로 도서관 DB 연동

### 4부. 설계와 정규화

**9장 — 데이터베이스 설계**
- 개념: 설계 단계, 요구사항 분석, 개념적 설계, 논리적 설계, 물리적 설계와 구현
- 매핑: 가상 "○○도서관" 요구사항 → 개념(ERD) → 논리(관계 스키마) → 물리(MySQL)로 전 과정 관통
- 실습: 종합실습 — 도서관 시스템 설계하기

**10장 — 정규화**
- 개념: 정규화 개념과 이상 현상, 함수 종속, 제1~제3 정규형·BCNF(및 제4 정규형 개요)
- 매핑: 저자 반복·출판사 중복이 있는 "나쁜 도서관 설계"를 단계적으로 정규화
- 실습: 평면 대출대장 → 3NF 분해

### 5부. 운영과 확장

**11장 — 회복과 병행 제어**
- 개념: 트랜잭션·ACID, 장애와 회복(로그·체크포인트), 병행 제어(락·직렬 가능성)
- 매핑: 대출/반납을 하나의 트랜잭션으로, 동시 예약·대출 충돌 시나리오
- 실습: `COMMIT`/`ROLLBACK`, 격리수준·락 관찰

**12장 — 보안과 권한 관리**
- 개념: 데이터베이스 보안, 접근 통제, 권한 관리(GRANT/REVOKE), SQL 인젝션 개요
- 매핑: 사서·이용자·관리자 권한 분리, 회원 개인정보 보호, 백업/복구
- 실습: 계정·권한 부여, `mysqldump` 백업

**13장 — 데이터베이스의 확장과 최신 데이터 기술**
- 개념: 관계 DB의 한계와 확장, 분산/병렬, 데이터 통합·분석 기반, 빅데이터·NoSQL, 클라우드 DB·AI, 데이터 마이닝·시각화
- 매핑: 대출 로그 빅데이터 분석, 도서 추천, 이용 통계 시각화, 전자책 메타데이터(문서형 NoSQL)
- 실습: 종합 프로젝트 — 도서관 데이터 분석·시각화 또는 NoSQL 확장 설계

## 5. 집필 로드맵(제안)

| 단계 | 산출물 | 비고 |
|---|---|---|
| **1단계** | 본 마스터 플랜 확정 | ← 현재 |
| 2단계 | 관통 스키마 v1 설계(`schema.sql` + `seed.sql`) | 7장 근거, 이후 모든 장의 토대 |
| 3단계 | 표본 1개 장 시범 집필(예: 7장 SQL) | 톤·분량·구성 템플릿 확정 |
| 4단계 | 1·2부(1~6장) 집필 | 개념·이론 중심 |
| 5단계 | 3부(7~8장) 집필 | SQL 실습 본격화 |
| 6단계 | 4·5부(9~13장) 집필 | 설계·운영·확장 |
| 7단계 | 부록·정답·색인 | 부속 자료 |
| 8단계 | 전체 교정·용어 통일 | 출판 준비 |
